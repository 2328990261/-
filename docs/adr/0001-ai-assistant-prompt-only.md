# AI 荐书：上下文走结构化 prompt，不上向量库/RAG

为「AI 荐书」助手注入上下文时，决定只使用结构化 prompt（用户画像 + 候选书池），不上独立向量数据库、不做 RAG。原因是书库元数据结构化且规模小（书名/作者/标签/热度），用户画像已完整，现有规则推荐引擎可直接产出 TopN 候选；向量检索则需要 embedding 模型、向量库与全文预处理，属于过重投入。若后续要做“按正文内容语义检索”，可在不推翻本方案的前提下补一个“简介”字段或复用已有 Redis 的向量存储。

**Status**: accepted

**Considered Options**
- 结构化 prompt：轻量、可解释、可复用现有画像与推荐引擎，足以满足当前推荐需求。
- RAG 向量检索：能按正文语义回答，但需 embedding + 向量库 + 全量预处理，复杂度与运维成本显著高于收益。

**Consequences**
- 模型的回答被限制在「候选书池」给出的书籍 ID 内，不能凭空荐书，也不能引用正文细节。
- 后续若要做“书内容问答”，需先引入简介/正文分块与向量检索，届时另立 ADR。
