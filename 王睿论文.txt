基于Springboot的轻小说推荐系统的设计与实现
摘  要
随着互联网技术的快速发展和数字阅读市场的不断扩大，轻小说作为一种新兴的网络文学形式，受到了越来越多年轻读者的喜爱。然而，当前轻小说推荐平台普遍存在推荐同质化、精准度不足等问题，难以满足用户个性化的阅读需求。本研究设计并开发了一套基于 SpringBoot 的轻小说推荐系统，采用前后端分离技术架构：前端运用 Vue.js 框架结合 ElementUI 组件库构建响应式操作界面，后端通过 SpringBoot 集成 MyBatis 实现 ORM 映射，配合改进的协同过滤推荐算法构建个性化推荐体系。系统设置多级功能模块：用户模块负责注册登录、个人信息管理及阅读行为采集；小说模块实现分类检索、章节阅读及收藏管理；推荐模块基于改进的 Item-CF 协同过滤算法结合标签匹配机制实现个性化推荐；后台管理模块完成小说资源管理、用户管理及数据统计等功能。数据库采用 MySQL 9.5 版本，设计包括小说主表、分卷表、章节表、用户表、收藏表、评论表、完读记录表、偏好标签表、阅读历史表及轮播图表等 10 张核心数据表，确保数据存储的完整性与查询效率。

关键词：轻小说推荐系统,SpringBoot 框架,Vue,协同过滤算法,MySQL 数据库









Design and Implementation of Light Novel Recommendation System Based on SpringBoot

With the rapid development of Internet technology and the continuous expansion of the digital reading market, light novels, as an emerging form of online literature, have been loved by more and more young readers. However, current light novel recommendation platforms generally have problems such as recommendation homogenization and insufficient accuracy, making it difficult to meet users' personalized reading needs. This study designs and develops a SpringBoot-based light novel recommendation system, utilizing a front-end and back-end separation technology architecture. The front end employs the Vue.js framework combined with the ElementUI component library to construct a responsive operation interface, while the back end integrates MyBatis through SpringBoot to implement ORM mapping, coupled with an improved collaborative filtering recommendation algorithm to build a personalized recommendation system. The system is equipped with multiple function modules: the user module is responsible for registration and login, personal information management and reading behavior collection; the novel module implements classification search, chapter reading and collection management; the recommendation module realizes personalized recommendation based on improved Item-CF collaborative filtering algorithm combined with tag matching mechanism; the background management module completes novel resource management, user management and data statistics. The database uses MySQL 9.5 version, designing 10 core data tables including novel main table, volume table, chapter table, user table, collection table, comment table, finished reading record table, preference tag table, reading history table and carousel chart table, ensuring data storage integrity and query efficiency.

Keywords: Light Novel Recommendation System, SpringBoot Framework, Vue, Collaborative Filtering Algorithm,MySQL Database

1.绪 论
1.1研究背景和意义
随着 5G 网络的普及和互联网的快速发展，据统计国内现已有超过 11 亿的人使用智能手机，智能手机的广泛使用已经从根本上改变了人们的日常生活方式。在数字阅读领域，网络文学市场规模持续扩大，其中轻小说作为一种源自日本、以年轻读者为主要受众的小说类型，近年来在国内获得了快速发展。
然而，当前轻小说推荐平台普遍存在以下问题：一是推荐同质化严重，用户难以发现符合个人口味的新作品；二是推荐精准度不足，无法准确捕捉用户的阅读偏好；三是系统开发门槛高，小型平台难以承担复杂的推荐系统开发成本。
结合本科阶段所学的Java Web开发、SpringBoot框架应用及数据库设计等核心知识，本设计聚焦轻小说阅读平台"推荐同质化"的精准度痛点，结合武晋科《网络小说阅读的心理特点与对策》[1] 中"读者追求情感共鸣"的核心结论，借鉴张新海等人《基于MVVM模式SpringBoot框架的高校信息化项目管理系统》[2] 的前后端分离核心设计，开发轻量化个性化推荐系统。
系统将通过记录用户阅读时长、收藏频率、章节完读率等行为数据，匹配其偏好的轻小说题材与叙事节奏；同时借助SpringBoot的自动配置、起步依赖特性简化开发，通过 MVVM 模式实现前后端高效联动，避免传统系统耦合问题。该设计既贴合专业学习核心，又能精准解决行业痛点，具备实际落地价值。

1.2 国内研究综述
国内近年来在网络文学相关系统与推荐技术领域的研究逐步深化，涌现出一批与本课题高度相关的实践成果。
在网络文学资源处理方面，王凯琪 [3] 网络小说信息爬取与管理系统，通过高效的数据抓取与分类存储机制，解决了小说资源获取与维护的核心问题，为轻小说推荐系统的数据源建设提供了成熟参考，但该系统未涉及个性化推荐功能，无法满足用户精准发现内容的需求。
在推荐算法应用层面，时光洋等人 [4] 基于标签匹配的推荐系统设计方案，通过提取作品标签与用户偏好标签进行匹配实现推荐，为轻小说推荐提供了基础思路，但该算法仅依赖单一标签关联，未考虑标签间潜在关联与用户行为权重，在处理复杂偏好时精准度有限，难以应对轻小说题材多样、用户兴趣多变的特点。
值得注意的是，雷宁 [5] 揭示了网络文学领域"注意力经济迭代"与"免费/付费模式差异"对用户阅读行为的影响，指出免费模式用户更倾向于碎片化、多题材尝试，付费模式用户则注重内容深度与连载连贯性，这一发现为轻小说推荐系统适配不同用户群体的阅读偏好提供了重要依据，但现有推荐系统尚未充分融合这类模式化用户行为特征，导致推荐场景适配性不足。
在系统架构搭建方面，基于SpringBoot+Vue技术栈开发的学生信息管理系统 [6]，采用前后端分离架构与模块化设计，验证了SpringBoot框架在简化开发流程、提升系统可扩展性方面的显著优势，为轻小说推荐系统的架构设计提供了切实可行的技术参考，尤其适配小型系统的开发需求。基于MVVM模式与SpringBoot框架的高校信息化项目管理系统 [2]，进一步证明了该框架在模块解耦、高效迭代方面的优势，为轻小说推荐系统的快速开发与后期维护提供了实践经验。李慧 [7] 基于B/S架构的数据共享网站系统的设计与实现，为系统架构设计提供了参考。
1.3 国外研究综述
近年来，国外在个性化推荐系统领域的研究已形成成熟体系，且在数字内容分发场景中积累了丰富实践经验。
在系统架构与应用实践层面，Liao 等人 [8] 提出的 DPBD 算法，通过解析用户借阅时长数据分离核心偏好与临时偏好，为图书类内容的推荐精准度提升提供了创新思路，该算法在轻小说这类叙事性内容推荐中具有直接借鉴价值。Su [9] 将 KGMRA 算法与 BERT 模型集成至 Spring 框架，构建了高效的阅读平台推荐架构，实现了算法与框架的深度融合，其模块化开发思路与性能优化策略已被多个数字内容平台采用。
但国外研究仍存在明显局限：一是场景适配性不足，现有成果多聚焦于影视、电商等大众领域，依赖高精度用户画像（如地理位置、消费能力），难以直接迁移至轻小说这类题材细分、用户群体集中于年轻群体的垂直场景；二是资源依赖度高，复杂模型多需要大规模计算集群支持，对于小型阅读平台而言部署成本过高，缺乏轻量化实现方案；三是忽略细分领域内容特征，未充分考虑轻小说在叙事节奏、题材标签、更新频率等方面的独特性，导致推荐匹配度不足。
1.4 研究目标
1.	设计并实现一套功能完备的轻小说个性化推荐系统，完成用户注册登录、小说检索阅读、用户行为采集、个性化推荐、后台资源管理及数据统计等核心功能，形成完整的业务闭环，有效改善轻小说推荐同质化问题，保证推荐结果的有效性与实用性。
2.	搭建轻量化、低耦合的前后端分离开发架构，熟练运用 SpringBoot 框架的分层设计思想完成后端开发，结合 Vue 实现前端页面搭建，确保系统运行稳定、操作便捷，满足小型轻小说平台的实际应用需求。
3.	对基础协同过滤算法进行场景化改进，融合标签匹配机制适配轻小说推荐场景，掌握推荐算法的工程化实现思路，完成系统功能测试与性能验证，形成规范的软件开发流程，巩固所学的数据库、框架应用及算法相关知识。
1.5 研究内容
本研究从轻小说推荐与阅读的数字化管理需求出发，在需求分析阶段梳理多角色使用场景与数据流，明确普通用户与后台管理人员在系统中的职责边界；结合本课题拟实现的轻小说推荐系统，将业务目标落实为可开发、可测试的功能划分。预计主要研究内容与功能对应关系如下。
（1）系统安全与权限
围绕系统安全性，研究并实现与业务相结合的访问控制：用户身份认证（如基于 JWT的登录态）、密码安全存储（如采用BCrypt等不可逆加密方式入库），以及前台与后台在路由与请求层面的区分——前端在访问需要登录或管理端的功能时携带令牌并依据用户身份标识进行路由控制，服务端在业务接口中对用户身份与管理员权限进行校验，使「谁能进入管理端、谁仅能使用用户端」在设计与实现上保持一致，为后续用户管理、资源管理等功能提供权限基础。
（2）用户与角色管理
研究并实现面向管理员的用户维护能力：在数据层以user表等结构支撑账号信息维护，在应用层提供分页查询、信息编辑、账号状态（如启用/禁用）等操作，使管理员能够对前台用户及后台管理员账号进行集中管理，保证角色职责与系统入口相匹配。
（3）普通用户：检索、阅读与个性化推荐
① 小说检索：支持按书名、作者、小说id等条件在书库中筛选与浏览，满足轻小说资源快速定位的需求。
② 章节阅读：支持从小说详情进入阅读页，并与阅读行为数据衔接；结合收藏、阅读历史等能力，形成「找书—读书—留存行为」的闭环。
③ 个性化推荐：基于用户偏好标签、评论热度、阅读历史等行为与内容数据，经推荐策略生成推荐结果，在首页等位置展示推荐列表，并与书库、收藏等模块联动，体现推荐业务在本系统中的实际落点。
（4）后台管理人员：小说资源与数据统计
① 小说资源管理：提供小说主数据、分卷与上架等业务维度的维护视图，支持新书发布、元数据维护与状态跟踪，与前台书库、阅读内容保持一致。
② 数据统计与展示：对推荐相关及运营关心的指标进行汇总，在管理端以概览与关键指标等形式展示（如书籍量、用户量、阅读量、收藏量等），便于观察系统运行与访问效果，支撑规范化运营分析，减轻人工统计误差。
在上述功能边界明确的前提下，本文将开展系统总体架构设计（前后端分离、接口与部署关系）、数据库设计（以novel_db及业务表为核心）、界面与交互设计（前台阅读体验与后台管理效率并重），并在实现阶段采用Vue 3+Vite与Spring Boot+ MyBatis等选型完成各模块开发，通过测试验证功能正确性、稳定性与基本安全性，形成一套可运行的轻小说推荐系统原型。
2 相关技术介绍
2.1 前端技术介绍
2.1.1 Vue框架
Vue 是渐进式前端框架，常与 Vite 等构建工具配合，适合开发需要较多交互的单页面应用。本系统前端采用 Vue 3，其核心机制包括响应式数据与组件化：当接口返回的书单、用户信息或页面状态发生变化时，视图会随之更新，减少大量手动操作 DOM 的工作。工程上可将导航栏、轮播、书库列表、阅读与推荐相关页面等拆分为独立组件，便于维护与复用 [6]。
2.1.2 Element UI
在 Web 开发中，使用成熟的组件库能提高表单、表格等常见界面的开发效率。Element Plus 是面向 Vue 3 的开源组件库（早期 Vue 2 版本对应组件库常称 Element UI，二者不宜混用名称）。本系统在部分页面中引入其轮播、卡片、表格等组件，与自研样式搭配，兼顾开发效率与界面统一性。
2.2 后端技术介绍
2.2.1 Java 语言
Java 具有「一次编写，到处运行」的跨平台特性，依托JVM在不同操作系统上提供相对一致的运行环境，有利于后端服务部署与迁移。语言层面以面向对象为主，便于将用户、小说、推荐等业务拆分为类与接口，使模块边界清晰、后续修改成本可控。围绕 Java 已形成成熟的工具链：本系统后端采用Spring Boot搭建Web与业务层，结合MyBatis访问MySQL，并通过Maven管理依赖与构建，能够较快完成接口开发与联调 [2]。
2.2.2 SpringBoot 框架
Spring Boot 建立在Spring生态之上，通过约定优于配置与自动装配，减少传统 Spring 项目中大量XML或样板配置，使开发者更聚焦于业务与接口实现。其内嵌 Servlet 容器（如 Tomcat），便于本地启动与部署，适合与本课题前后端分离、以REST 风格接口对外提供数据的架构。借助Spring Boot Starter可按需引入Web、数据访问、安全等能力，与MyBatis、JWT等组件配合，能够支撑本系统用户认证、小说与推荐等模块的后端开发[2]。
2.2.3 MySQL 数据库
MySQL是常用的关系型数据库，适合存储本系统中用户、小说主数据、分卷、收藏、评论、阅读历史、标签与推荐配置等结构化业务数据。借助事务的 ACID 特性，可保证注册、收藏、写评论、记阅读时长等操作在并发访问下仍具一致性，降低数据错乱风险。通过为常用查询字段建立索引、在表之间使用外键或逻辑关联，有利于提升书库检索、按用户查询行为数据等操作的效率。本系统采用MySQL（文中版本号与学校要求及实际安装环境保持一致即可），以十余张核心数据表组织业务数据，支撑前后端分离架构下的持久化需求 [7]。
2.2.4 协同过滤推荐算法
协同过滤推荐算法（Collaborative Filtering Algorithm）在推荐算法领域备受关注，并且是广泛应用的技术之一。相较于传统的推荐算法，它具有较为显著的优势。协同过滤算法能够通过分析用户历史行为数据（如阅读记录、收藏、点击行为等），通过识别并计算具有相似偏好的用户群体之间的相似度来执行任务。然后依据这些用户对小说的评价或偏好，为目标用户推荐他们可能感兴趣的小说，以此实现个性化推荐 [10]。
协同过滤推荐方法主要分为三类：基于用户的协同过滤、基于项目的协同过滤及基于模型的协同过滤。基于用户的协同过滤聚焦于找出与目标用户有相似喜好的其他用户，而基于项目的协同过滤则是识别出与用户之前喜欢的项目相似的其他项目，基于模型的协同过滤算法则使用各种机器学习模型来预测用户对物品的评分或偏好 [10]。
3 需求分析
3.1 项目功能分析
3.1.1 项目目标
本系统面向轻小说数字化阅读与推荐需求，在角色上划分为用户与管理员：用户侧重小说发现、阅读与互动；管理员侧重小说资源维护、用户与权限管理、推荐与标签等参数配置及运营数据查看。系统将实现用户注册与登录、小说检索与章节阅读、收藏与评论、阅读行为与偏好采集、推荐列表展示，以及后台的小说上架与维护、用户与管理员账号管理、推荐与系统配置、基础数据统计等功能，形成「前台阅读—行为沉淀—后台配置与维护」的完整业务闭环。
3.1.2 功能需求分析
1. 用户功能需求
账户与访问：注册、登录、退出；基于JWT令牌维护登录态，访问个人中心、收藏、评论等需登录的功能。
小说检索与浏览：在首页、书库等页面按关键词检索作品（书名、作者等），并通过标签栏按题材/标签筛选；首页可按阅读量等热度信息浏览列表。
阅读与详情：查看小说详情与分卷章节，进入阅读页进行章节阅读；系统可记录阅读历史等行为数据，支撑推荐与统计。
互动与偏好：收藏作品；发表评论；在个人中心维护阅读偏好标签（如收藏排序、自定义标签等），并在推荐页获取与偏好相关的推荐结果。
2. 管理员功能需求
管理员通过后台入口访问管理端（前台路由依据用户身份进行控制），主要需求包括：
用户与权限：在用户管理中维护注册用户基本信息与账号状态（如启用/禁用）；在管理员管理中维护具备后台权限的账号；权限区分采用用户是否管理员等标识实现。 
小说资源：通过书籍上架录入或发布小说主数据、分卷与章节；在书籍管理中维护上架状态与原数据，保证前台书库与阅读内容与库内数据一致。
推荐与基础配置：在推荐配置、配置管理等页面调整推荐策略相关参数（如标签权重、评论与阅读历史在推荐中的参与方式等）；在系统设置（标签）中维护平台标签及推荐权重等。
内容与展示：按需维护首页轮播图等资源位。
数据统计：在概览等页面查看书籍量、用户量、阅读量、收藏量等汇总指标，支撑管理员快速了解系统运行概况。
3.2 可行性分析

熟悉并掌握SpringBoot、Java、Vue、MySQL数据库、协同过滤算法等方面的编程技巧和方法，对于这些技术该有的软硬件配置也是齐全的，能够满足开发的需要。本轻小说推荐系统采用的是MySQL作为数据库，可以绝对地保证用户数据的安全；IDEA 作为开发工具，通过SpringBoot框架可以与MySQL数据库进行无缝连接。所以，轻小说推荐系统在现有基础上是能够实现的。

4 系统设计
4.1 总体系统结构设计
基于Spring Boot的轻小说推荐系统遵循常见分层思想，采用B/S架构与前后端分离开发模式：表示层为基于Vue的前端应用，负责界面展示与交互，内部可采用MVVM思想组织页面与数据；业务逻辑层为基于Spring Boot的后端服务，封装用户、小说、推荐等业务与算法逻辑；数据持久层通过MyBatis完成与MySQL的数据访问与映射。前后端通过REST风格接口交互，前端使用Axios发起 HTTP 请求，数据以JSON为主进行传输。
4.2 系统功能模块划分
本系统实现了与前后端交互所需要的基本功能：安全控制、权限管理、后端数据初始、业务功能模块的管理及控制前后端传递数据所需的后端工具类。

4.2.6 后台管理模块设计
后台管理端与前台读者端分离，仅管理员可进入。整体按功能菜单划分模块，模块之间通过统一布局（侧栏导航+内容区）组织，数据上依赖用户权限标识区分访问范围。
（1）概览
数据看板：集中展示书籍、用户、阅读、收藏等汇总指标，供管理员快速掌握平台规模与活跃概况。
（2）书籍上架
新书入库：完成小说主信息与分卷内容的登记及上架控制，是用户端可读内容的来源模块。
（3）书籍管理
在库作品维护：支持查询与信息修正、上下架调整等，与上架模块分工为「新增」与「维护」。
4）用户管理
管理用户：支持检索、分页浏览、信息编辑与账号状态控制，并与「是否管理员」等权限字段衔接。
（5）管理员管理
管理员后台账号：单独维护具备管理端访问权限的账号，与普通用户管理对象不同、职责分离。
（6）推荐设计
提供简单的推荐规则配置功能，管理员可调整不同标签的推荐权重，灵活控制推荐结果的展示优先级，适配平台的运营需求。
（7）配置管理
扩展型配置：聚合首页轮播图、推荐行为权重等相对独立的运营配置项，便于后续增加配置类型。
（8）回到首页
为路由出口：结束后台操作并返回前台站点，完成管理端与用户端的场景切换。


4.3 数据库设计
本管理系统的数据库软件主要应用MySQL9.5版本的数据库系统，并且利用 Navicat以实现数据库管理设计可视化开发。
4.3.1 数据库概念设计
概念模型设计主要通过 E-R 图描述实体、属性及联系。结合本系统数据库，主要实体包括：
用户（User）：user，存储账号、联系方式、管理员标识与状态等。
小说主表（NovelBookMain）：存储小说主信息（书名、作者、标签、封面、阅读量、上下架等）。
分卷（Volume）：关联主书，存储分卷名称及正文内容。
标签（Tag）：存储平台标签及推荐权重、排序等。
收藏（Collection）：用户与小说的收藏关系及收藏时间。
评论（Comment）：用户对小说的评论及时间。
完读记录（FinishedNovel）：用户完读某本小说的记录。
用户偏好标签（PreferenceTag）：用户侧偏好/排序用标签。
阅读历史（ReadingHistory）：阅读进度、时长、最近阅读时间等。
轮播图（BannerCarousel）：首页轮播及关联小说、展示时段、点击统计等。
推荐行为权重配置（RecommendCommentConfig）：评论与阅读历史参与推荐时的权重与开关。

5 系统实现
5.1 用户登录模块
本系统为管理员与普通用户提供登录入口。用户需在页面中输入账号和密码，点击登录后，系统先做前端校验：检查是否按要求填写（例如不能为空、长度是否符合约定等）。若未通过，只在登录页给出提示，不跳转到系统首页。
前端校验通过后，系统将账号密码提交至后端，由服务器在数据库中查找对应用户，并核对密码是否正确，同时结合业务判断账号是否允许登录（例如是否被禁用）。若用户名不存在、密码不匹配或账号不可用，则返回相应提示，用户仍停留在登录页，不进行首页跳转。
登录验证通过后，服务端采用JWT（JSON Web Token）机制为本次会话生成访问令牌：令牌中携带与当前用户相关的必要信息，用于后续请求中标识用户身份。前端将令牌保存在浏览器本地，在访问需要登录的资源时自动随请求携带，避免重复输入密码。令牌具有有效期，过期后原有令牌不再被认可，用户需重新登录以获取新令牌，从而降低凭证被长期盗用的风险，提升系统安全性。
登录成功后进入系统首页；系统根据用户身份（如是否为管理员）在导航等处区分可见功能，便于用户按权限使用系统。
除账号密码登录外，系统还提供手机号登录方式：用户输入手机号并获取验证码后，验证码会在当前页面中直接显示，便于在开发与演示环境下完成登录流程验证；日常使用中，用户仍以账号密码登录为主。
5.2 用户注册模块
用户在登录页点击「立即注册」即可进入注册页面。注册时需填写账号、密码，并再次确认密码；点击注册按钮后，系统先在页面侧进行基本校验：账号长度是否符合约定（如 3～20 个字符）、密码长度是否符合约定（如 6～20 个字符）、两次密码是否一致等。若未通过校验，则在当前页提示，不提交注册。
校验通过后，前端将注册信息提交至后端；服务端查询数据库，若用户名已被占用，则拒绝注册并返回提示信息，用户需更换账号后重新提交。若用户名可用，则将新用户信息写入数据库：其中密码在入库前使用BCrypt（基于Spring Security提供的密码加密组件）进行加密存储，避免明文保存；新用户默认登记为普通用户（不具备后台管理权限），可在前台进行浏览、阅读、收藏等与读者身份相符的操作。注册成功后，系统会按与登录一致的流程生成 JWT 访问令牌并返回用户信息，前端保存登录状态，并跳转至系统首页，使用户注册完成后即可直接使用系统。
5.3 用户功能模块
5.3.1 个人信息管理
系统允许管理员在此页面修改用户信息、根据不同输入查询指定用户、删除（选中多个批量删除）用户信息、根据业务需求，确定系统业务人员职责范围，通过权限分配按钮为身份是系统业务人员的用户分配相应权限功能，新注册用户默认分配设备出租和归还权限。提供左侧部门树快捷查询相应部门功能，新注册用户默认部门为"用户"。

5.3.2 阅读偏好设置
用户在登录后进入个人中心，可在「阅读偏好」区域设置自己关注的题材方向，用于配合推荐与展示顺序。系统提供两种工作方式：一是按收藏与阅读行为自动形成的偏好排序（收藏排序），数据随行为更新，一般无需手动保存；二是自定义排序，用户可在界面上增删自己关心的标签，并从系统提供的标签范围内进行选择，确认后保存写入数据库，以便后续推荐或列表展示使用。
服务端为偏好标签提供查询、批量保存与单条删除等接口，持久层通过MyBatis将上述操作映射为对user_preference_tag等表的增删改查，保证每位用户的偏好数据相互独立、可维护。
5.3.3 行为记录
用户行为在个人中心等界面汇聚与阅读相关的数据，为推荐与统计分析提供依据。 
1.数据采集与存储：
系统在用户阅读、收藏、评论、标记完读等操作时，将相应信息写入数据库，主要包括：阅读历史（如阅读进度、时长、最近阅读时间等）、收藏关系、完读记录、评论等。上述数据与用户偏好标签共同支撑推荐模块中的标签偏好与行为加权策略。
2.界面与交互：
用户在个人中心可查看阅读行为概览（如收藏数量、完读数量、阅读时长汇总等），并在「我的书架」中按「正在读」「已看完」等维度浏览与跳转至作品详情；阅读偏好可与收藏、自定义标签联动保存。
5.4 用户端功能模块
5.4.1 小说检索
用户在书库可通过关键词检索作品：支持按书名、作者等字段进行模糊匹配；当关键词为纯数字时，系统可按作品编号进行定位。检索条件可通过导航栏搜索跳转至书库并带入关键词，书库内也可再次输入关键词查询；系统可记录搜索历史便于重复访问。
此外，用户可通过标签栏按标签进行多选筛选，与关键词检索相互配合：标签筛选用于缩小题材范围，关键词用于精确定位书名或作者。
检索结果以列表形式展示小说封面、书名、作者等基本信息，用户可点击进入详情页继续阅读或收藏。
5.4.2 章节阅读
用户从小说详情进入阅读页，加载该作品对应分卷中的文本内容（分卷表存储解析后的正文，阅读页按章节/分页进行展示与切换）。用户在同一页面可完成上一章/下一章、翻页、返回详情等操作，并可配置字体大小、护眼模式、页面宽度/版面等阅读参数，以提升长时间阅读体验。
系统在用户阅读过程中可记录阅读行为：例如将阅读进度、时长等信息写入阅读历史表，供个人中心「我的书架」与推荐使用；用户可在阅读页进行收藏、发表评论（需登录）、以及将作品标记为已看完等操作，与收藏、评论、完读记录等数据表相对应。
5.4.3 收藏管理
收藏管理用于建立登录用户与平台小说之间的收藏关系，便于读者标记常读或感兴趣的作品。业务数据持久化在用户收藏表（user_collection）中，主要记录用户ID、小说主卷ID及收藏时间；表上对「用户—小说」建立唯一约束，避免同一用户对同一部作品重复收藏。
在功能上，已登录用户可在小说详情页与在线阅读页执行「收藏/取消收藏」；前端调用后端接口完成写入或删除，并可在进入页面时查询当前用户对该书是否已收藏。收藏成功后，用户可在个人中心的「我的书架」中查看以收藏为基础的列表：其中「正在读」与「已看完」等视图与阅读进度、完读标记等行为数据配合使用，共同构成个人阅读状态的总览；个人中心还提供收藏小说数量等阅读行为统计，以及基于收藏作品标签的收藏排序偏好展示（与自定义偏好标签并列，用于后续推荐等模块）。
5.5 推荐功能模块
5.5.1 模块定位
推荐功能模块是本系统的核心业务之一，面向已登录用户在推荐页提供作品列表。与首页按阅读量排序、面向全体读者的「热门浏览」不同，本模块在用户设置阅读偏好后，结合平台标签体系与行为数据，生成差异化推荐结果；未登录用户可在推荐页看到与书库类似的浏览方式，个性化推荐能力主要在登录后启用。
5.5.2 基于标签的协同过滤思想与实现要点
推荐计算采用基于标签的协同过滤思想：将用户兴趣与作品特征统一映射到标签空间，通过标签命中与加权衡量用户与作品之间的匹配程度；在此基础上，再辅以评论热度、阅读历史关联等行为信号进行修正与排序。 
用户标签权重值根据用户行为进行实时变更（本系统设计方案）：为每位用户维护各标签的权重值（有初始值）。当用户产生阅读、收藏、评论等行为时，系统从对应作品的标签字段中解析题材标签，对参与行为的标签进行统计与权重更新（设上下限以防异常漂移），使权重随用户真实行为动态变化，从而反映其阅读偏好演变。推荐打分阶段，将用户当前标签权重与作品标签进行匹配累加，并可与全站标签基准权重、评论热度、近期阅读历史等项组合，得到最终排序依据。
5.5.3 管理端功能与配置
1. 概览
展示平台运行关键指标：书籍总数、用户总数、总阅读量、总收藏数等，以卡片形式汇总。管理员进入后台后首先查看本页，快速判断内容规模与用户活跃概况，不包含业务数据的增删改，仅作统计展示。
2. 书籍上架
用于新作品入库，一般分步完成：先创建主卷信息（书名、作者、多选标签（与前台标签栏同源）、封面上传等），再维护分卷与正文（如上传EPUB等并完成解析入库）。流程结束后作品写入小说主表与分卷表，供前台书库与阅读页使用。该模块是前台「可读内容」的主要来源。
3. 书籍管理
用于已入库作品的日常维护。支持按首行标签快捷筛选、按书名/作者搜索，以及按上架/下架状态过滤；列表展示 ID、封面、书名、作者、标签、阅读量、状态等。管理员可进入编辑修改主数据与标签、更换封面、调整上下架等，保证前台展示与库内数据一致。
4. 用户管理
面向普通注册用户。提供按用户名/邮箱搜索、按账号状态筛选及分页浏览。对单条用户可编辑用户名、邮箱、电话、是否管理员、状态等，可选修改密码（后端以BCrypt 存储）；支持禁用/启用账号。用于日常账号治理与异常账号处理。
5. 管理员管理
面向管理员账号，与用户管理对象分离。同样支持检索、状态筛选、分页与单条编辑（含是否管理员、状态、密码等），用于控制谁具备后台访问权限，避免与普通用户混在同一维护视图中操作。
6. 推荐配置
以表格形式列出平台全部标签，针对每条标签维护其在推荐计算中使用的推荐权重（数值可调、按行保存），数据对应标签表中的推荐权重字段，页面提示评论与阅读历史类权重在「配置管理 → 推荐行为权重」中设置。 

7. 配置管理（配置管理中心）
作为多项运营配置的入口页，以卡片跳转子功能为主。当前主要包括：轮播图管理（首页轮播图片、链接、排序等）；推荐行为权重（评论热度是否参与、权重上限、阅读历史是否参与、单本书加分、统计最近阅读条数等）。
8. 系统设置（标签）
维护平台标签库本身：支持标签新增、编辑、删除，配置推荐权重、排序等，该模块侧重标签作为基础数据的完整 CRUD；推荐配置页则侧重在推荐场景下批量查看与调权重，推荐配置页便于「按推荐视角集中调权重」）。



9. 回到首页
结束后台会话布局，路由跳转回前台站点首页，便于管理员以读者身份查看上架与配置效果，完成「管理—验证」闭环。

6.19 测试小结
本系统测试共设计十七张用例表（表 6-1～表 6-17），覆盖账号密码登录、注册、手机验证码登录、首页与书库、详情与评论、在线阅读与个人书架、推荐页、书籍上架（封面上传、主书创建、EPUB 分卷解析入库）、后台书籍/用户/管理员管理、推荐配置与推荐行为权重、轮播图与系统标签管理及安全性与权限；其中后台首页数据概览（`AdminDashboard` 调用 `/api/admin/stats/overview` 汇总书籍数、用户数、阅读量、收藏数）在联调中与库内聚合结果一致，与上述管理模块一并验收。与当前工程中的页面与控制器划分基本一致。实际部署时可将「实际结果」列与演示录像、接口日志交叉核对；后续可在此基础上增加性能测试（并发访问、大 EPUB 上传）、兼容性与安全性渗透测试，以进一步完善质量保障。
